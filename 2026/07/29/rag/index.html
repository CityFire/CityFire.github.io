RAG 检索增强生成技术

发表于2026-07-29|更新于2026-07-29|AI
|阅读量:

RAG初识

1. 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是当前大语言模型落地最核心、最主流的技术方案。它解决了大模型知识滞后、幻觉严重、私有数据无法适配、答案无依据四大核心痛点。

传统大模型的能力完全依赖训练时的参数知识，属于静态知识库：训练数据截止后，无法获取最新信息，也无法学习企业私有文档、业务数据。而 RAG 通过「先检索、后生成」的范式，将外部私有知识库的实时内容注入大模型上下文，让模型基于真实、准确的外部资料生成答案。

2. RAG 核心价值

  • 消除幻觉：答案全部基于检索到的真实文档，杜绝编造信息

  • 知识实时更新：无需微调模型，更新知识库即可更新模型认知

  • 低成本落地：相比模型微调，RAG 成本极低、迭代快、无灾难性遗忘风险

  • 可溯源可解释：答案可绑定原文出处，满足企业合规要求

  • 适配私有业务：完美适配企业文档、知识库、工单、产品手册等私有数据

3. RAG 与传统微调的区别

维度 RAG 检索增强 LLM 微调 Fine-tune
知识存储位置 外部向量库（动态可改） 模型参数权重（静态固化）
更新成本 极低，仅更新文档和向量 极高，需要重新训练、调参、算力支撑
幻觉问题 大幅抑制，有据可依 无法根治，仅能优化风格
数据安全 数据不进模型权重，安全性高 训练数据会残留权重，存在泄露风险
适用场景 知识问答、私有知识库、实时资讯 风格统一、指令对齐、能力强化

4. RAG 完整核心流程

RAG 整体分为两大阶段：索引构建阶段（离线）、问答推理阶段（在线）

  1. 离线索引构建：原始文档 → 清洗 → 分块 → 向量化 → 存入向量数据库

  2. 在线问答推理：用户提问 → 问题向量化 → 向量检索 → 重排筛选 → 上下文拼接 → LLM 生成答案

RAG索引的构建

索引构建是 RAG 系统的地基环节，索引质量直接决定检索准确率，最终影响整体问答效果。索引构建的核心目标：将非结构化原始文档，转化为可被向量检索引擎高效查询的结构化索引数据。

1. 索引构建全流程

原始文档采集 -> 数据清洗 -> 文本预处理 -> 智能分块 -> 元数据绑定 -> 文本向量化 -> 向量入库构建索引

2. 各环节核心细节

2.1 原始文档采集

支持多源数据接入：PDF、Word、Markdown、网页、数据库文本、工单日志、知识库文章等，统一归一化为纯文本格式。

2.2 数据清洗

过滤无效噪声数据，避免脏数据影响向量精度：

  • 去除页眉页脚、目录、页码、水印、空行、特殊符号

  • 过滤重复文本、无意义乱码、格式标签

  • 统一换行、空格、标点格式

2.3 元数据构建

每一个文本块都需要绑定元数据，用于后续过滤、溯源、权限控制：文档来源、文档标题、更新时间、章节、页码、权限标签、业务分类等。

2.4 向量索引构建

文本块经过 Embedding 模型转化为固定维度向量后，存入向量数据库。向量库会自动构建近似最近邻索引（ANN），替代暴力遍历，实现毫秒级检索。

3. 主流索引类型

  • FLAT：暴力精准检索，小数据量使用，速度慢、精度100%

  • IVF：倒排聚类索引，平衡速度与精度

  • HNSW：分层导航小世界图，工业界主流，速度极快、精度高

4. 索引更新机制

  • 全量重建：定时全量重新分块、向量化、建索引，适合低频更新场景

  • 增量更新：仅新增/修改文档重新索引，旧数据保留，适合高频迭代知识库

  • 冷热更新：热点文档常驻缓存，冷文档异步更新索引

RAG文档分块

文档分块（Chunking）是 RAG 最关键的核心优化点，分块策略直接决定检索效果。分块过短会丢失上下文、语义断裂；分块过长会冗余信息过多、向量相似度偏移、超出上下文窗口。

1. 主流分块策略

1.1 固定大小分块（基础版）

按照固定字符长度切割文本，搭配滑动窗口重叠（Overlap）解决上下文断裂问题。

  • 优点：实现简单、速度快、成本低

  • 缺点：容易切割语义完整句子、段落，破坏语义完整性

  • 适用：简单公开文本、通用知识库

1.2 语义分块（进阶版）

通过句子向量相似度判断语义边界，语义差异大的位置自动切割，保证每一块都是完整语义单元。

  • 优点：语义完整性极高，检索精准度大幅提升

  • 缺点：计算成本更高、速度慢于固定分块

1.3 层级分块（高级版）

构建「文档-章节-段落-句子」多层级块结构，检索时先粗筛大模块，再精筛细粒度内容，兼顾全局语义和细节精准度，是当前企业级 RAG 最优方案。

1.4 结构化分块

针对 Markdown、PDF、Word 等结构化文档，基于标题层级、段落、表格、列表原生结构分块，不破坏文档原有逻辑。

2. 分块核心参数调优

  • 块大小 Chunk Size：通用场景 300–800 字符，专业技术文档 500–1000 字符

  • 重叠大小 Overlap：块长度的 10%–20%，解决边界语义丢失

  • 最小块阈值：过滤过短无效碎片块

3. 分块常见问题与规避方案

  • 语义割裂：开启重叠分块、语义分块优化

  • 关键信息碎片化：层级分块+后续重排聚合

  • 无效块过多：增加前置清洗、阈值过滤

RAG文本向量化

文本向量化（Embedding）是将自然语言文本转化为高维稠密向量的过程，是 RAG 语义检索的数学基础。机器无法直接理解文字，只能通过向量空间距离判断文本语义相似度。

1. 向量化核心原理

语义相似的文本，在高维向量空间中距离更近；语义无关的文本，向量距离更远。通过计算余弦相似度、欧氏距离、内积，即可实现语义检索，而非传统关键词匹配。

2. 主流 Embedding 模型

  • 通用开源模型：bge-m3、text2vec、sentence-transformers，支持多语言、轻量高效

  • 商用模型：OpenAI Embedding、阿里Embedding、讯飞Embedding，精度更高、适配通用场景

  • 垂直领域模型：法律、医疗、教育专属 Embedding，垂直场景效果碾压通用模型

3. 向量相似度计算方式

3.1 余弦相似度（最常用）

忽略向量长度，只关注语义方向，适配长短文本匹配，是 RAG 检索默认方案。

3.2 内积

适合归一化后的向量，计算速度最快，工业界高频使用。

3.3 欧氏距离

关注向量整体差异，对文本长度敏感，RAG 场景极少使用。

4. 向量化最佳实践

  • 统一向量维度：检索向量与入库向量必须来自同一个 Embedding 模型

  • 向量归一化：统一向量模长，提升相似度匹配稳定性

  • 禁止混合模型：不同 Embedding 模型向量无法通用匹配

  • 批量向量化：批量推理提升吞吐，降低接口调用成本

RAG检索重排

检索重排是 RAG 系统的精度提升核心模块。基础向量检索速度快、召回率高，但存在语义匹配不准、噪声内容多、相似度虚高的问题。重排（Rerank）的作用是：对粗筛结果做精准二次打分，筛选出最贴合用户问题的高质量文本块。

1. 检索-重排二级架构

一阶粗检索：向量库快速召回 Top-K（Top20/Top50）结果，保证高召回率，不漏信息

二阶精重排：Rerank 模型对召回结果逐一对问题做相关性打分，筛选 Top3–Top10 最优内容，保证高精度

2. 重排核心优势

  • 解决向量检索语义模糊、匹配偏差问题

  • 过滤无关、冗余、弱相关文档块

  • 大幅提升最终生成答案的准确性和相关性

  • 降低 LLM 上下文负担，减少无效信息干扰

3. 主流 Rerank 模型

  • bge-reranker：开源最强通用重排模型，轻量、高精度

  • cross-encoder：经典交叉编码重排模型

  • 商用付费重排接口：阿里、腾讯、百度智能重排服务

4. 高级检索优化策略

4.1 问题改写/Query 增强

对用户原始问题进行扩写、同义改写、拆分子问题，解决短句歧义、语义模糊导致的检索失效问题。

4.2 混合检索（关键词+向量）

向量检索负责语义匹配，BM25 关键词检索负责实体、专有名词精准匹配，两者加权融合，兼顾语义和关键词精准度。

4.3 上下文压缩

重排后对文本块做精简、去冗余、核心信息提炼，最大化利用有限上下文窗口。

GraphRAG原理

传统向量 RAG 是扁平化语义匹配，只能做到「问题-文本块」的相似度匹配，无法理解文档中的实体关系、逻辑链条、知识关联，面对复杂推理、多文档关联、因果问答场景效果极差。GraphRAG 基于知识图谱构建结构化知识，解决传统 RAG 弱推理、无关联的短板。

1. GraphRAG 核心定义

GraphRAG 是知识图谱 + 检索增强生成的进阶 RAG 架构，通过从文档中自动抽取实体、属性、关系，构建文本知识网络，实现关联检索、逻辑推理、多源知识聚合。

2. GraphRAG 核心要素

  • 实体 Entity：文档中的核心概念、人物、产品、流程、指标、术语

  • 关系 Relation：实体与实体之间的关联（包含、导致、属于、流程先后、关联）

  • 属性 Attribute：实体的特征、参数、状态

  • 知识子图 SubGraph：围绕核心实体聚合的局部知识网络

3. GraphRAG 构建流程

  1. 文档解析分块：原始文档预处理、分块清洗

  2. LLM 知识抽取：批量抽取实体、关系、属性

  3. 知识融合消歧：统一实体别名、合并重复关系、清洗错误关联

  4. 构建知识图谱：生成结构化知识网络

  5. 图谱+向量双索引：同时存储向量索引与图谱关系索引

4. GraphRAG 问答推理流程

  1. 用户提问，解析问题中的核心实体

  2. 基于实体遍历知识图谱，获取关联实体、关系、子图

  3. 结合向量检索召回关联文本内容

  4. 融合结构化图谱知识 + 非结构化文本知识

  5. LLM 基于完整知识网络完成推理、归纳、问答

5. GraphRAG vs 传统向量RAG

能力维度 传统向量 RAG GraphRAG
知识形态 扁平化文本碎片 结构化关联知识网络
推理能力 弱，仅相似度匹配 强，支持多步关联推理
复杂问题适配 差，容易答不全、答不准 优秀，适合归纳、对比、溯源、流程问答
构建成本 低 较高（需知识抽取与融合）

6. GraphRAG 适用场景

  • 复杂业务流程问答、链路溯源

  • 产品体系、层级、关联关系查询

  • 故障因果分析、问题溯源推理

  • 多文档交叉关联、知识归纳总结

  • 企业复杂知识库、体系化知识问答

总结

传统 RAG 通过分块、向量化、检索重排解决大模型知识滞后与幻觉问题，是工业界落地的基础方案；而 GraphRAG 在传统 RAG 基础上升级了结构化知识关联与推理能力，是复杂企业级 AI 知识库的未来演进方向。掌握从索引构建、分块策略、向量检索、重排优化到 GraphRAG 进阶原理，可完整覆盖 90% 以上的大模型落地场景。
